TUTORIEL D'INSTALLATION DE FINDER
==================================

Ce tutoriel explique comment installer et lancer l'API Finder avec Node.js,
MySQL, Laragon et Prisma.


1. Logiciels requis
-------------------

Installer :
- Node.js LTS
- Laragon, ou un serveur MySQL équivalent
- Git, si le projet est récupéré depuis GitHub
- Visual Studio Code, recommandé pour ouvrir le projet

Vérifier Node.js dans PowerShell :

node --version
npm --version


2. Récupérer le projet
----------------------

Depuis le dossier où le projet doit être installé :

git clone https://github.com/Ga3TH/projet-finder.git
cd projet-finder

Si le projet est déjà présent, ouvrir PowerShell à sa racine et vérifier sa
structure :

Get-ChildItem

La racine doit notamment contenir les dossiers `api`, `docs`, `front` et
`script`. Le serveur se trouve dans `api/src/server.js`.


3. Installer les dépendances
----------------------------

Le projet Node se trouve dans `api`. Installer les dépendances depuis ce
dossier :

cd api
npm install

Toutes les dépendances sont installées dans `api/node_modules`. Les dossiers
`node_modules` sont générés localement et ne doivent pas être commités.


4. Démarrer MySQL et créer la base
-----------------------------------

1. Ouvrir Laragon.
2. Cliquer sur "Start All".
3. Vérifier que MySQL est démarré.

Avec une installation Laragon classique :
- utilisateur : `root`
- mot de passe : vide
- serveur : `localhost`
- port : `3306`

Dans HeidiSQL, créer une base appelée `finder` si elle n'existe pas encore :

CREATE DATABASE finder;

Ne pas créer les tables manuellement : Prisma les crée avec les migrations.


5. Configurer l'environnement
-----------------------------

Depuis le dossier `api`, copier le fichier d'exemple :

Copy-Item .env.example .env

Le fichier `api/.env` doit contenir, avec MySQL par défaut :

PORT=3000
DATABASE_URL="mysql://root:@localhost:3306/finder"

Si MySQL utilise un mot de passe :

DATABASE_URL="mysql://root:MOT_DE_PASSE@localhost:3306/finder"

Remplacer `MOT_DE_PASSE` par le vrai mot de passe. Adapter aussi le port si
MySQL n'utilise pas `3306`.

Le fichier `.env` reste local et ne doit pas être envoyé sur GitHub.


6. Préparer la base avec Prisma
-------------------------------

Toutes les commandes suivantes se lancent depuis `api` :

npx prisma generate
npx prisma migrate deploy

Le schéma utilisé est `api/prisma/schema.prisma`.

Pour ajouter les données de démonstration :

npm run db:seed

Le seed remplace les données existantes dans les tables puis ajoute les
hôtels, chambres, comptes et réservations prévus par le projet.


7. Vérifier le projet
---------------------

Toujours depuis `api` :

npm run check
npx prisma validate
npm test

`npm test` lance les tests présents dans le dossier `api/tests`. S'il n'y a
pas encore de tests, Node indiquera simplement qu'aucun test n'a été trouvé.


8. Démarrer l'API
-----------------

Important : lancer la commande depuis `api`, et non depuis `api/src` :

cd C:\chemin\vers\projet-finder\api
npm run dev

Message attendu :

API sur http://localhost:3000

Pour un lancement sans redémarrage automatique :

npm start

Pour arrêter le serveur : `Ctrl + C`.


9. Tester l'API
---------------

Ouvrir un deuxième terminal sans arrêter le serveur :

curl.exe http://localhost:3000/health
curl.exe http://localhost:3000/hotels
curl.exe http://localhost:3000/chambres
curl.exe "http://localhost:3000/chambres?hotel=Amor"
curl.exe "http://localhost:3000/chambres?hotel=Amor&prixmax=100"

La route de santé doit répondre :

{"statut":"ok"}

Routes disponibles :
- `GET /health`
- `GET /hotels`
- `GET /hotels/:id`
- `GET /hotels/:id/chambres`
- `GET /chambres`
- `GET /chambres/:id`


10. Ouvrir Prisma Studio
------------------------

Depuis `api` :

npx prisma studio

Puis ouvrir :

http://localhost:5555

La commande s'écrit `prisma`, pas `prima`.


11. Problèmes fréquents
-----------------------

`npm` n'est pas reconnu :
Installer Node.js LTS, puis fermer et rouvrir PowerShell.

`npm run dev` ne démarre pas :
Vérifier que le terminal est dans `projet-finder/api`, et non dans `api/src`.

La connexion MySQL échoue :
Démarrer MySQL dans Laragon et vérifier `DATABASE_URL` dans `api/.env`.

Le port 3000 est déjà utilisé :
Arrêter l'ancien serveur ou choisir un autre port dans `api/.env`.

Prisma ne trouve pas les tables :
Lancer `npx prisma migrate deploy`, puis `npm run db:seed` depuis `api`.

Aucune chambre ne s'affiche :
Vérifier que le seed a été exécuté et que les paramètres de l'URL sont
corrects, par exemple `hotel=Amor` ou `categorie=double`.
